# MVP plan A: developer-first rewrite of `iris_basics.py`

Written 2026-09-30 against baseline `37a6e0f`. This is the contract for one scaffold agent and
four column builders working in parallel. Every fact about an API shape comes from the research
briefs under `.agents/research/*-2026-09-30.md` (their VERIFIED tags) or from the 2026-09-30 live
run recorded in README "Verified live" and plan section 10. Where this plan and a brief disagree,
the brief wins on API facts and this plan wins on scope.

## 0. The angle, in five rules the builders must obey

The reader is a developer who has never seen Redis Iris and has 20 minutes. Every cell is judged
against these rules; a cell that fails one is rewritten or cut.

1. **Fewest cells that show the component doing its one job end to end.** One job per column:
   Search answers a question over your own data; LangCache returns a stored answer for a
   paraphrase; Context Retriever turns three classes into MCP tools over your Redis; Agent Memory
   recalls a fact by meaning. Everything else is either the setup for that job or the Clean up.
2. **Plain code a reader can retype into a script.** No helper stands between the reader and
   `redis-py` or `niquests` except the two in the setup cell (`call_service`, `connect_redis`).
   No functions defined inside column cells. No `mo.state`, no generation tokens, no callbacks.
   A `for` loop and a list comprehension are the most advanced Python allowed.
3. **Request and response shown raw with `mo.json`.** Every HTTP cell renders the wire dict
   `call_service` returns (method, URL, masked headers, body, status, ms) and the parsed reply.
   Every Redis cell renders the redis-cli line rebuilt from the argv redis-py sends.
4. **At most one interactive control per example.** A text box, a slider, or a dropdown. Never
   two on the same example. Buttons that gate writes do not count.
5. **Cut anything that needs a sentence to justify itself.** If the lead-in has to explain why
   a mechanism exists (a re-scoring trick, a prediction table, a floor probe), the mechanism goes.

Consequences worth stating up front: the LangCache threshold cell re-queries the server on every
slider release instead of re-scoring locally (six requests per move, honest about who applies the
cut); the Agent Memory threshold lesson is two fixed searches, not a sweep; Context Retriever
makes two fixed `tools/call`s instead of a form generator; column 0's full-text and pre-filter
examples have no control at all.

## 3. The notebook skeleton

```python
import marimo

__generated_with = "0.25.0"
app = marimo.App(width="columns", app_title="Redis Iris basics")


with app.setup(hide_code=True):
    import json
    import os
    import re
    import time
    import uuid
    from datetime import datetime, timedelta, timezone

    import marimo as mo
    import niquests
    import numpy as np
    import redis
    from redis.backoff import ExponentialBackoff
    from redis.retry import Retry

    RUN_TAG = uuid.uuid4().hex[:8]          # one tag on everything this kernel writes
    KEY_PREFIX = f"cairn:{RUN_TAG}:"        # every Redis key this notebook writes starts here
    KEY_TTL_SECONDS = 3600                  # every Redis key expires on its own within the hour
    MASKED_HEADERS = {"authorization", "x-api-key"}

    def call_service(session, method, path, *, json_body=None, params=None):
        """One request to an Iris service. Returns (status, body, wire); wire is safe to show."""
        response = session.request(method, path, json=json_body, params=params)
        sent = response.request                      # the PreparedRequest that went on the wire
        body = None
        if response.content:
            try:
                body = response.json()
            except ValueError:
                body = response.text
        headers = {k: "***" if k.lower() in MASKED_HEADERS else v for k, v in sent.headers.items()}
        wire = {
            "method": sent.method,
            "url": sent.url,
            "headers": headers,
            "body": json.loads(sent.body) if sent.body else None,
            "status": response.status_code,
            "ms": round(response.elapsed.total_seconds() * 1000),
        }
        return response.status_code, body, wire

    def connect_redis(url):
        """A redis-py client with the production settings the Redis docs recommend."""
        return redis.Redis.from_url(
            url,
            protocol=2,                              # flat FT.* replies; every shape here was verified under RESP2
            decode_responses=True,                   # strings back; the vector field is never read through a core command
            socket_connect_timeout=5,
            socket_timeout=5,
            retry=Retry(ExponentialBackoff(), 3),    # 3 retries on ConnectionError / TimeoutError
            health_check_interval=30,                # PING before reuse after 30 s idle
        )
```

That is the whole setup block: imports, the run tag and its two constants, one HTTP helper, one
Redis helper. Nothing else may be added to it. Column cells are `@app.cell(column=N)`; markdown
cells add `hide_code=True`; every cell is a named function (`def rs_title():`) so tracebacks
and `marimo check` name it. Markdown is always `mo.md(r"""...""")` (triple-quoted, so
`check --strict` passes MF007). No cell contains only `pass`.

Two marimo rules every builder must respect: a UI element's `.value` is read in a different cell
from the one that creates it; a `run_button` result cell depends only on the button, the column's
connect-cell names, setup names and `cairn_support` imports, so it never re-runs (and resets to
"press the button") because a slider moved.

### 0.5 `rs_question` and 0.6 `rs_knn_versus_range`

Lead-in on 0.6: "The cell below embeds your question and runs it twice: `KNN 3` always returns
the three nearest articles, and `VECTOR_RANGE 0.5` returns only those within that cosine
distance. Ask `best pizza near me` and KNN still returns three rows while the range query
returns none. KNN could never say this, and that empty answer is what LangCache calls a MISS."

Code: `rs_query_vector_bytes = embed_texts(rs_embedding_model, [rs_question.value])[0].tobytes()`;

### 1.1 `lc_title`

> # 1. Redis LangCache
>
> Users rarely ask the same question the same way twice, and an exact-key cache misses every
> rewording. Redis LangCache matches on meaning: it embeds the prompt, searches the cache, and
> returns the stored answer when the similarity clears a threshold, so the model is not called.
> A match is a score above a line, so a wrong answer for a question that only sounds similar is
> possible. The threshold is the dial, and this column turns it.
>
> LangCache is in public preview on Redis Cloud. Settings: `LANGCACHE_HOST`,
> `LANGCACHE_CACHE_ID`, `LANGCACHE_API_KEY`. Docs: [LangCache](https://redis.io/docs/latest/develop/ai/context-engine/langcache/),
> [API reference](https://redis.io/docs/latest/develop/ai/context-engine/langcache/api-reference/).

Mermaid: `flowchart LR; P[Prompt] --> S[POST /entries/search]; S -->|similarity >= threshold| H[Stored answer]; S -->|data: empty| L[Call the LLM]; L --> W[POST /entries with ttlMillis]`.

### 3.1 `am_title`

> # 3. Redis Agent Memory
>
> An agent that forgets a user's allergy between sessions is not unintelligent; it has no
> memory. Redis Agent Memory gives it two tiers: session memory, the ordered events of the
> conversation in progress, and long-term memory, facts recalled by meaning across sessions.
> You write facts directly or let the service extract them from sessions in the background,
> and you search them with an owner id and a namespace on every call, because the store is
> shared by every app that points at it.
>
> Agent Memory is in preview. Settings: `MEMORY_API_BASE_URL`, `MEMORY_STORE_ID`,
> `MEMORY_API_KEY`. Docs: [Agent Memory](https://redis.io/docs/latest/develop/ai/context-engine/agent-memory/),
> [REST quickstart](https://redis.io/docs/latest/develop/ai/context-engine/agent-memory/rest-api-quickstart/).

## 15. Risks and open questions for the orchestrator

1. **Live re-query on the LangCache slider** costs six requests per release. Rate limits are
   undocumented; the live run made 23 searches without meeting one. If a 429 appears, the row
   shows it and the reader waits. The alternative (search once at 0.5, re-score locally) is
   fewer requests but needs a justifying sentence, which this angle forbids.
2. **`get_customer_by_id` argument name.** The live run sent `{"id": "C001"}`; the conformance
   review wrote `customer_id`. Cell 2.7 hard-codes `id`; the builder must confirm against
   `cr_tools[...]["inputSchema"]["required"]` on the first live run and fix the literal if needed.
3. **The rejected call's exact reply** (`-32602` with a schema message) is plausible, not
   verified; cell 2.8 prints whatever arrives and has an "accepted" branch.
4. **Radius 0.5 in cell 0.6** rests on an offline calibration (paraphrase about 0.22, unrelated
   about 0.83). One live run should confirm `best pizza near me` misses and `will it fit my feet`
   hits; adjust the literal, not the design.
5. **`time.sleep(11)` in cell 1.9** blocks the kernel for 11 seconds; marimo shows the spinner.
   Acceptable for a scripted proof; say so in the lead-in if a reviewer objects.
6. **Two controls in column 3** are avoided by fixing the threshold lesson at 0.0 and 0.3; if a
   live run on another store shows nothing at 0.3, change the literal and the sentence, not the
   cell.
7. **`Content-Type: application/json`** is pinned on every session so the untested
   `;charset=utf-8` variant never reaches the services.
8. **Python 3.11** is locked but untested at runtime (packaging brief). Decide before `uv lock`
   whether to keep the marker split or raise the floor to 3.12.
9. **`disable_http3=True`** on each session is one kwarg a reader may ask about; the comment says
   "keeps the wire view identical run to run". Drop it if plainness outranks determinism.
10. **A `run_button` result cell resets** when any dependency above it re-runs (for instance if
    the connect cell re-runs). The result cells depend on connect-cell names and the button only,
    so this happens only on a kernel restart, but the README troubleshooting entry covers it.
11. **LangCache after a kernel restart** cannot delete the previous kernel's entries; the
    15-minute `ttlMillis` is the net, stated flat in the README.
12. **Context Retriever cleanup when create failed halfway**: `cr_surface_id` is undefined and
    cell 2.11 cannot run; the surface (if created) is named `cairn-<run>` in the console. The
    README says so under Troubleshooting.
13. **pytest 9.1.1** with marimo's own notebook collector is unverified; the suite does not use
    the collector (it calls `app.run()` itself), so only `pytest iris_basics.py` would be affected.
14. **The `Customer`/`Product`/`Order` class names** break the `cr_` prefix rule on purpose; a
    comment in cell 2.3 says the service names tools after the classes.
