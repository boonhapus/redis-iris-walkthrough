## Summary

LangCache is a managed semantic cache with a five-endpoint REST API (search, set, delete by id, delete by attributes, flush) under `{baseUrl}/v1/caches/{cacheId}`. Auth is `Authorization: Bearer <service key>`. The published OpenAPI spec is at https://redis.io/docs/latest/develop/ai/context-engine/langcache/api-reference/api.yaml, and the docs live at /develop/ai/context-engine/langcache/. The official Python SDK is `langcache==0.14.0` (PyPI, 2026-08-24, Python >=3.10). It has sync methods plus `*_async` twins and is a thin wrapper over httpx and pydantic. I confirmed the SDK's exact wire format (paths, camelCase body, Bearer header) by pointing it at a local loopback mock server. Nothing touched a live service.

The SDK is ahead of the published spec. `max_results` (wire name `maxResults`, "Defaults to 1") and `conversational_search` (POST `/conversations/search`, takes `context`, returns `actualPrompt`) exist in the SDK from 0.12.0. Neither appears in api.yaml. Treat both as usable but unverified against the live service.

The shared-cache risk is real and asymmetric. The live Iris demo app searches with no `attributes` (backend/app/langcache_service.py:44-49, backend/app/main.py:481), so attributes cannot protect the demo from notebook entries. Attributes only protect the notebook from the demo's entries, and only if the cache defines attribute names at creation, which cannot be edited later. The real protections are:
- a short per-entry `ttl_millis`;
- prompts that sit far from every demo domain;
- delete-by-id cleanup of tracked `entryId`s;
- never calling `flush()` or `delete_query(attributes={})`. Both delete the whole cache, and the SDK sends `{"attributes":{}}` for an empty dict, which I confirmed on the wire.

The Console's "Generate key" rotates the API key and immediately kills the old one, which would break the live demo. Reuse the existing key instead. Best isolation is a separate LangCache service for the notebook. Note the demo's own `make setup`, `make reset` and `make seed-langcache` flush the whole cache (scripts/seed_langcache.py:38), so notebook entries are ephemeral anyway.

A no-LLM-key notebook is fully viable. Embeddings are done server-side by the service's configured provider, and the notebook can use canned or "taught" answers. The strongest wow designs use the `similarity` score the server returns: one low-floor search per probe prompt, then a client-side threshold slider. Saved outputs in the workshop notebook give real anchors: exact prompt 1.000, paraphrase 0.906, another paraphrase 0.839, unrelated a miss at threshold 0.82.

## Verifier corrections (authoritative)

- **Claim:** The demo code's 'no attributes are configured' substring match is 'the only evidence for that error string', and the search-side behavior (search with attributes against a cache that has none configured) is undocumented.
  - **Correction:** A second Redis-authored codebase matches the same string. redisvl 0.27.2 checks `isinstance(e, BadRequestErrorResponseContent) and "no attributes are configured" in str(e).lower()` on search/check (about lines 321-336 and 398-413) and on store (about lines 470-485), then raises a RuntimeError. The RedisVL docs also say: 'If you pass metadata to store or attributes to check but the cache has no attributes configured, the LangCache API returns an error.' So the string is corroborated, and it applies to SEARCH too. A scoped search on an attribute-less cache will 400; it does not silently return everything.
  - **Source:** uv run --no-project --with redisvl (0.27.2): site-packages/redisvl/extensions/cache/llm/langcache.py; https://docs.redisvl.com/en/latest/user_guide/13_langcache_semantic_cache.html
- **Claim:** mo.ui.slider(start, stop, step, value, debounce, show_value, include_input, *, label, on_change)
  - **Correction:** The real positional order is start, stop, step, value, debounce, disabled, orientation, show_value, include_input, steps, then keyword-only label, on_change, full_width. That holds in both 0.24.2 and 0.25.0. Passing show_value as the 6th positional would actually set disabled, so use keywords.
  - **Source:** inspect.signature(mo.ui.slider) under marimo==0.24.2 and marimo==0.25.0
- **Claim:** `entry.model_dump(by_alias=True)` gives the camelCase form, and the WIRE VIEW can show the SDK body with `SearchRequest(...).model_dump(by_alias=True, exclude_none=True)`.
  - **Correction:** The keys come out camelCase, but the enum values stay Python enum objects. You get 'searchStrategies': [<SearchStrategy.SEMANTIC: 'semantic'>] and 'searchStrategy': <SearchStrategy.SEMANTIC>. For true wire JSON use `model_dump(by_alias=True, mode='json')` or `model_dump_json(by_alias=True)`. Both give ['semantic'], and SearchRequest's serializer already drops None optionals.
  - **Source:** $TEMP/lcfc/probe2.py run with langcache==0.14.0
- **Claim:** conversational_search(..., context: list[str]|None=None, ...)
  - **Correction:** The annotation is `context: Iterable[str] | None`, which is coerced to List[str]. This is harmless in practice.
  - **Source:** inspect.signature(LangCache.conversational_search), langcache 0.14.0
- **Claim:** Typed errors' `.data` carries title/type/status/detail.
  - **Correction:** The list is incomplete. BadRequestErrorResponseContentData also has `instance` and `fields: Optional[List[FieldError]]`, which carries field-level validation errors worth showing for a 400. `.data.type` is an enum (e.g. BadRequestErrorType.ROOT_ERRORS_INVALID_DATA), not a plain string.
  - **Source:** langcache/errors/badrequesterrorresponsecontent.py (0.14.0); loopback mock output
- **Claim:** The LangCache savings calculator link https://redis.io/calculator/langcache/ is unverified (verified=false).

  - **Source:** curl -sL https://redis.io/calculator/langcache/ | grep title; the overview page's href

### Verifier: additional facts

## 2. REST (OpenAPI 3.0.2 at https://redis.io/docs/latest/develop/ai/context-engine/langcache/api-reference/api.yaml; SDK-only rows marked)
Base = `{URL from Console}/v1/caches/{cacheId}`. The spec's `servers` entry is a localhost placeholder. Example real host: `https://aws-us-east-1.langcache.redis.io` (RedisVL docs).
Headers: `Authorization: Bearer <service API key>`, `Content-Type: application/json`, `Accept: application/json`.

| Op | Request | Success |
|---|---|---|
| search | `POST /v1/caches/{cacheId}/entries/search` body `{"prompt": str (req, 1-1024 chars), "similarityThreshold": float 0..1, "attributes": {str:str}, "searchStrategies": ["exact"\|"semantic"], "maxResults": int (SDK-only, "defaults to 1")}` | 200 `{"data":[{"id":"<32 hex>","prompt","response","attributes":{},"similarity":0..1,"searchStrategy":"exact\|semantic"}]}`. `data` is `[]` on a miss. |
| set | `POST /v1/caches/{cacheId}/entries` body `{"prompt": str (req, 1-1024), "response": str (req), "attributes": {<=5 props}, "ttlMillis": int 1..31556952000}` | 201 `{"entryId":"<32 hex>"}` |
| delete by id | `DELETE /v1/caches/{cacheId}/entries/{entryId}` | 204 no body. 404 `/errors/cache/entry/not-found` if it already expired. |
| delete by attributes | `DELETE /v1/caches/{cacheId}/entries` body `{"attributes": {...}}` (JSON body on DELETE) | 200 `{"deletedEntriesCount": n}`. **Empty or absent attributes deletes EVERYTHING** (spec text and docs WARNING). |
| flush | `POST /v1/caches/{cacheId}/flush` | 204 |
| conversational search (SDK-only) | `POST /v1/caches/{cacheId}/conversations/search` body = search body + `"context": ["Q1","Q2",...]` | 200 `{"actualPrompt": str, "data":[CacheEntry...]}` |

- Attribute constraints on `set` (SetEntryRequest): at most 5 properties; name regex `^[a-zA-Z0-9_-]{1,32}$`; value string of 1-500 chars matching `^[^,]*$` (no commas). "All attribute names that can be associated with an entry must be defined during cache creation."
- `searchStrategies` is "ordered by priority". Default is `["semantic"]` only. `exact` is a case-insensitive whole-prompt match.
- Error body (RFC 7807-like): `{"title","status","detail","type", ["instance"]}`.
  - 400 `/errors/invalid-data`
  - 401 `/errors/authentication-failed`
  - 403 `/errors/insufficient-permissions`
  - 404 `/errors/cache/not-found`, `/errors/cache/entry/not-found`, `/errors/resource/not-found`, `/errors/token/not-found`
  - 413 `/errors/payload-too-large`
  - 424 `/errors/database/resource-database-unavailable`, `/errors/database/out-of-memory`, `/errors/embeddings/unauthorized`, `/errors/embeddings/too-many-requests`, `/errors/cache/index-not-found`
  - 429 `/errors/too-many-requests`
  - 500 `/errors/unexpected-error`, `/errors/cache/authentication`, `/errors/cache/unexpected-error`, `/errors/embeddings/unexpected-error`
- There is NO `distance` field in responses, only `similarity` ("normalized cosine similarity"). There is no top-k or limit param in the published spec.
- If using raw httpx instead of the SDK: `httpx.Client.delete()` has no `json=` parameter (verified, httpx 0.28.1), so use `client.request("DELETE", url, json={...})`.

## 4. Safe-usage sketch for the notebook (design, not yet run against a live service)
```python
SESSION_TAG = f"iris-basics-{uuid.uuid4().hex[:8]}"   # unique per session; passes the value regex (no commas)
ENTRY_TTL_MS = 30*60*1000                              # ALWAYS pass ttl_millis so leaked entries self-expire
MY_IDS: set[str] = set()                               # every entry_id returned by set()
def put(prompt, response, scope_attr):                 # scope_attr = user-supplied attribute NAME already defined on the cache, or ""
    kw = dict(prompt=prompt, response=response, ttl_millis=ENTRY_TTL_MS)
    try:
        r = lc.set(**kw, attributes={scope_attr: SESSION_TAG}) if scope_attr else lc.set(**kw)
    except BadRequestErrorResponseContent:             # demo service treats 400 "no attributes are configured" as "retry without attributes" (langcache_service.py:91-93)
        r = lc.set(**kw)
    MY_IDS.add(r.entry_id); return r.entry_id
def cleanup():
    for i in list(MY_IDS):
        try: lc.delete_by_id(entry_id=i)
        except NotFoundErrorResponseContent: pass     # already TTL-expired
        MY_IDS.discard(i)
# scoped sweep, only if scope_attr and SESSION_TAG: lc.delete_query(attributes={scope_attr: SESSION_TAG})
# guard: assert attributes non-empty before ANY delete_query call. NEVER call lc.flush().
```
Search from the notebook with `attributes={scope_attr: SESSION_TAG}` when scoping is available. Otherwise search unscoped and filter results client-side by `entry.id in MY_IDS`, using `max_results>1` if the server honors it.

## Explorable parameters

- **similarity_threshold** — Minimum normalized cosine similarity for a semantic hit. Per-request override of the cache default. Values: Spec range 0..1 (float). Console cache-level range 0.5..1.0, Redis default 0.85, recommended start 0.8-0.9. The demo uses 0.82. Redis's tutorial uses 0.65. Observed similarities: exact 1.000, FD paraphrases 0.906 / 0.839, password paraphrase 0.833. Use a slider 0.50..1.00 step 0.01. _(src: api.yaml SearchEntriesRequest.similarityThreshold; concepts page; Console create/edit page)_
- **search_strategies** — How a lookup is matched: `exact` (case-insensitive whole-prompt equality) and/or `semantic` (embedding similarity), ordered by priority. The returned `searchStrategy` says which one produced the hit. Values: ["semantic"] (default and what the demo sends), ["exact"], ["exact","semantic"]. Great for a case/whitespace/punctuation probe table. _(src: api-examples docs; api.yaml SearchStrategy enum)_
- **attributes (search filter and entry tag)** — String key/value tags on entries. A search with attributes returns only entries carrying them, and delete_query removes only entries carrying ALL given attributes. This is the only scoped cleanup other than delete-by-id. Values: <=5 per entry; names must be pre-defined on the cache at creation (immutable afterwards); name regex ^[a-zA-Z0-9_-]{1,32}$; value 1-500 chars, no commas. Suggested: {<scope_attr>: 'iris-basics-<8hex session id>'}. _(src: api-examples; api.yaml SetEntryRequest.attributes; create-service docs)_
- **ttl_millis (per entry)** — Entry lifetime in ms. If omitted, the cache default (Console default 'No expiration') applies. Doubles as a leak-containment safety net on the shared cache. Values: 1..31,556,952,000 ms. Suggested: 30 min for normal entries, 5-10 s for the TTL demo. _(src: api.yaml SetEntryRequest.ttlMillis; SDK `set(ttl_millis=)`)_
- **max_results** — How many candidate entries a search returns. Server default is 1. Larger values let the notebook show near-neighbours and filter out entries it does not own. SDK-only (0.12.0+), not in the published spec. Values: int >=1. Unverified server-side max. _(src: SDK 0.14.0 SearchRequest docstring)_
- **context (conversational_search)** — Chronological list of earlier user questions [Q1,Q2,...]. The service reformulates the follow-up prompt (CQR) before searching and returns `actual_prompt`. SDK-only and experimental. Values: list[str] _(src: SDK 0.14.0 ConversationalSearchBody)_
- **prompt text variants (the probe set, not an API parameter)** — The interesting explorable axis for teaching. Include true paraphrases, lexical near-misses with a different intent, entity or number swaps, negations, casing/whitespace changes, and unrelated prompts, each with an expected hit/miss label so the notebook can score false hits. Values: Prompt 1-1024 chars. Keep the probe domain fictional and away from the seven demo domains. _(src: concepts page FAQ ('Could I get back a response for a different question? Yes'); saved workshop outputs)_
- **cache-level settings (display only, not changeable from the notebook)** — Embedding provider/model, default threshold, default TTL, attribute schema are set in the Console. The notebook can only mention them and link to the Configuration page. Values: n/a _(src: view-edit-cache docs)_

## Wow ideas

- CACHE-FIRST CHAT with no LLM key. `mo.ui.chat` model callback: `lc.search(prompt=msg, similarity_threshold=cfg['threshold'], attributes=scope, max_results=...)`. A hit returns `mo.md` with the cached answer plus a badge line (HIT 0.913 | matched prompt 'original' | strategy semantic | 38 ms | entry id). A miss returns 'MISS, no answer cached' and remembers `last_miss`. A `mo.ui.text_area` plus 'Teach it' button then calls `lc.set(prompt=last_miss, response=text, ttl_millis=..., attributes=...)`, and the presenter re-asks a paraphrase to get a live HIT. Seed `prompts=[...]` chips with paraphrase families. Read the threshold from a mutable dict updated by `slider.on_change`, so moving the slider does not reset the chat.
- THRESHOLD LAB. Seed 3-4 entries in a fictional domain. Run each probe (about 15-20: paraphrases, near-misses, entity/number swaps, negations, unrelated) ONCE at a floor threshold of 0.5 with max_results=1 and record (probe, best matched prompt, similarity, expected label). Then a `mo.ui.slider(0.5, 1.0, 0.01)` re-scores client-side with no network calls: the table recolors hit/miss/false-hit/missed-paraphrase, `mo.stat` cards show precision, recall and hit rate, and a line marks the first threshold where a false hit disappears. Teaches 'similar is not the same' straight from the concepts-page warning. Depends on the unknown that per-request threshold can go below the cache default (see unknowns).
- WIRE VIEW ('anatomy of a request') accordion under every code cell. Show the exact JSON the SDK sends (`SearchRequest(...).model_dump(by_alias=True, exclude_none=True)` or the captured body) and the raw response JSON with `similarity` and `searchStrategy`, plus the equivalent curl. This makes the two-call cache-aside architecture (search -> LLM on miss -> set) visible for architecture teaching.
- EXACT vs SEMANTIC vs HYBRID side-by-side. One `mo.ui.dropdown` of strategy lists over the same probe prompts (case flips, trailing punctuation, paraphrases). A table shows which strategy answered and the similarity. It shows why exact is cheap and safe and semantic is the recall booster.
- ATTRIBUTE SCOPING / TENANT ISOLATION. Store the same question with different answers under scope values A and B (needs a cache with a defined attribute; otherwise show the card disabled with a link to the attributes docs). A `mo.ui.radio` picks the tenant, and the same prompt returns different answers. Ends with a 'Clean up my entries' button that calls `delete_query` on the unique session tag (guarded to be non-empty) and prints `deleted_entries_count`.
- TTL EXPIRY. Store with `ttl_millis=8000`, then `mo.ui.refresh(options=[1,2])` polls the search: HIT, HIT, then MISS after expiry. Shows time-based invalidation with zero infrastructure. Also shows a 404 on delete-by-id for an already-expired entry.
- SAVINGS METER. Replay a scripted stream of 30-50 prompts (built from paraphrase families) through the real cache. Show live hit-rate, real measured cache latency (perf_counter) against a user-set assumed LLM latency and $/1M output tokens (`mo.ui.number`), using the docs formula savings = output-token cost x hit rate, rendered with `mo.stat` cards. Link to the Console Metrics tab and https://redis.io/calculator/langcache/.
- CONVERSATIONAL FOLLOW-UPS (experimental). `lc.conversational_search(prompt='and what about pricing?', context=['Tell me about Acme skates'])` shows the reformulated `actual_prompt` next to the raw prompt, demonstrating how multi-turn chat can still use a semantic cache. Wrap in try/except and skip gracefully if the endpoint is not available for the cache.
- ZERO-CREDENTIAL FALLBACK. If no credentials are set, run the same wow cells against the local model2vec plus numpy simulation already in redis-iris-basics/notebook.py, clearly labelled 'simulated', so the notebook always runs for a presenter. This is an idea only; the user's criteria favour near-zero setup.

## Safety concerns

- ASYMMETRIC LEAK RISK. The live demo app's search sends NO attributes (backend/app/langcache_service.py:44-49) with threshold 0.82 (settings.py:70 default). Any notebook entry, tagged or not, is therefore eligible to be served as an answer in the demo if a demo user's prompt scores >= the demo threshold against it, with no LLM call and no way for the app to tell. Attributes only protect the NOTEBOOK from the demo's entries, not the reverse (the unscoped-search behavior is inferred, not observed live). Worst case: a generic notebook FAQ such as 'What is your refund policy?' or 'How do I reset my password?' hijacks reddash, electrohub or radish-bank answers.
- Mitigations to build in, in order of strength: (1) a dedicated LangCache service/cache for the notebook, the only true isolation (Quick create; whether a second service fits on the same free database is unknown); (2) always pass a short `ttl_millis` (about 30 min) on every `set`, so leaked entries self-expire; (3) keep all notebook prompts in a fictional domain far from the demo domains (banking/FD rates, electronics returns, appointments, delivery refunds, phone trade-in, bet settlement, stock fundamentals), and avoid generic support-FAQ phrasing, ideally with a distinctive product name in every prompt; (4) track every returned `entry_id` in memory and delete by id at the end (a 'Clean up' button plus an atexit or final cell); (5) tag entries with `{scope_attr: 'iris-basics-<uuid8>'}` when the cache defines an attribute, so scoped sweeps (`delete_query` on that unique tag) are safe.
- FLUSH IS DESTRUCTIVE. `lc.flush()` (POST /flush) and `lc.delete_query(attributes={})` both erase every entry in the shared cache, including the demo's seeded answer. The SDK serializes an empty dict as `{"attributes":{}}` (verified on the wire) and the spec says empty/absent attributes deletes all. The notebook should never expose flush, and its delete helper should `assert` a non-empty attributes dict that contains the unique session tag. The Console's Flush button is the same operation.
- KEY ROTATION BREAKS THE DEMO. The Console's 'Generate key' immediately invalidates the old API key, so the live demo and `make setup` would start failing (its store/search catch exceptions and silently treat search failures as misses, langcache_service.py:69-72, which would look like 'LangCache never hits' rather than an auth error). Tell the presenter to reuse the existing key, never regenerate it on the shared service.
- REVERSE CONTAMINATION. The demo's seed script flushes the WHOLE cache on `make setup`, `make reset` and `make seed-langcache` (scripts/seed_langcache.py:37-39), silently deleting any notebook entries and invalidating an in-progress live notebook demo. Conversely, an unscoped notebook search can return the demo's seeded entry (e.g. radish-bank FD rates) instead of the notebook's own. Fictional-domain prompts plus client-side filtering by tracked entry ids handle both.
- ATTRIBUTE FALLBACK IS AN UNDOCUMENTED STRING MATCH. The demo detects 'no attributes configured' by substring-matching a 400 response text, which is not in the published docs. The notebook should catch `BadRequestErrorResponseContent` generally (any 400 on a set with attributes), retry once without attributes, and clearly tell the user it is in unscoped mode with the extra cleanup care that implies. A search that names an undefined attribute may also 400. Probe this once, up front, with a tracked `set`.
- SECRETS HYGIENE. LANGCACHE_API_KEY is a bearer credential. Use `mo.ui.text(kind='password')` or environment variables, never echo it in cell output, and do not paste it into the notebook file. The notebook should print only host, cache id and the last 4 characters of the key. The `.env` values in redis-iris-demos were never read; only key names were listed.
- COST AND LIMITS. Every search and set triggers an embedding call on the service's provider (if the service was created with an OpenAI key, calls bill that account). 424 `/errors/embeddings/*` and 429 errors exist. Keep the threshold-lab sweep small (about 20 sequential searches), and surface errors (status, `type`, `detail`) instead of silently reporting a miss the way the demo does.

## Unknowns

- Does the live service honor a per-request similarityThreshold BELOW the cache's configured default (0.85 by default, console range 0.5-1.0)? The threshold-lab wow (one low-floor search per probe, then a client-side slider) depends on it. Spec range is 0..1 and the docs are silent. Verify on the first live run by searching a known paraphrase at threshold 0.5 and confirming a similarity below 0.85 comes back.
- Does the live Redis Cloud service honor `maxResults`, and are results sorted by descending similarity? It is in SDK 0.12.0+ but not in the published api.yaml.
- Does `POST /conversations/search` (conversational_search, CQR) exist for Redis Cloud caches or is it gated/self-managed only? It is SDK-only and undocumented in the spec. Treat the conversational wow as optional and wrap it in try/except with a friendly fallback.
- What exact error does the live service return when (a) the cache has no attributes configured, or (b) the attribute name is not one of the configured names? The demo code implies HTTP 400 with the text 'no attributes are configured' for case (a). Case (b) and the search-side behavior are undocumented. The design should catch BadRequestErrorResponseContent broadly and degrade to unscoped mode.
- Does the user's shared cache define any attributes at all (names/count)? Their code suggests `domain` and `topic` may exist but that is unconfirmed, and attributes cannot be added later. Ask the user or have the config cell probe with one `set` call.
- Is an entry that has attributes returned by a search that specifies a different attribute or none? Is an entry WITHOUT the attribute excluded from a scoped search? Undocumented. Assume exclusion and test.
- Does `set` de-duplicate identical prompts or create a new entryId every time? Not documented. Track every returned entryId to be safe.
- Does the server treat `{"attributes": {}}` on DELETE /entries as 'delete all'? The spec says absent attributes means delete all. Never test this on the shared cache.
- Is the `similarity` for strategy `exact` always 1.0, and how does a hybrid ['exact','semantic'] search report which strategy won? The `searchStrategy` field exists, but its behavior when both match is not documented.
- Whether a second LangCache service can be created on the same free 30MB database (Quick create uses it), or whether one service per database is the limit. That would be the cleanest isolation for the notebook.
- Rate limits, free-tier quotas and per-call embedding cost (a 429 error type exists but no numbers are published). A threshold sweep of ~20 probe searches should be fine but is untested.
- Whether entries expire exactly at ttlMillis (search miss immediately after) or on a coarser sweep. Matters for the TTL demo timing.
- The Redis Cloud console has a deep-link URL for the LangCache page that I could not verify (SPA). Only https://cloud.redis.io/ plus the left-menu path is confirmed.
