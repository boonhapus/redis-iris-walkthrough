## Summary

Redis Search is built into Redis 8.x, and Redis Cloud docs say all Redis Stack capabilities are included by default from 8.0, so there is no "tick Search at creation" checkbox. Essentials databases older than 8.0 also include Redis Stack automatically; only Pro databases older than 8.0 ever had the checkbox. The old README and notebook claim (notebook.py:213-214, README.md:33-36) is stale and wrong for Essentials. The free tier is far tighter than the old design assumed: one free DB per account, 30 MB, 30 connections, 100 ops/sec, 5 GB/month, and TLS is NOT available on the free plan. The old placeholder and README table that say `rediss://` for Redis Cloud (notebook.py:200, README.md:30) would fail on a free DB; the free URL is `redis://default:<pw>@<host>:<port>`. Redis Cloud offers Essentials versions 8.6, 8.4, 8.2, 7.4 and 7.2 (8.0 is not available for new databases). FT.HYBRID needs 8.4 or later, and SVS-VAMANA needs 8.2 or later; whether the free tier can pick those versions or run SVS is not documented, so the notebook should feature-detect and try/except them. Current PyPI: redis 8.1.0 (2026-07-30, it exists and is the latest), redisvl 0.27.2, model2vec 0.9.0 (latest), marimo 0.24.2 (exists, but 0.25.0 shipped 2026-09-23). Recommendation: use raw redis-py `execute_command` for the column, since visible FT.CREATE/FT.SEARCH is the architecture lesson. redisvl 0.27.2 emits byte-identical query strings (shown below), so put it in a collapsed "same thing in redisvl" cell and keep it out of the inline deps. Embeddings: model2vec plus minishlab/potion-base-8M is 256-dim, unit-normalised, and 61.4 MB on disk (all 10 repo files, including a 30 MB ONNX file you don't need). It downloads in about 7 s. On Windows, `force_download=False` is silently a no-op in model2vec 0.9.0 (a backslash-path bug), and a verified workaround is given below. sentence-transformers is too heavy: 42 vs 24 resolved packages, a 124 MB torch wheel and a 91 MB model. The audit found reusable pieces (the `_cli` renderer, tracer, embedder cell, KNN-vs-VECTOR_RANGE lesson, consent/teardown) and real defects: `rediss://`, the stale Search claim, guard gaps (FT.DROPINDEX/FT.SEARCH on any index, multi-key DEL, empty PREFIX), pipelines bypassing the guard, and a router whose SORTBY MAX 1 runs before FILTER. Nothing here was run against a live Redis. All server-side behaviour is from docs or client source, and every live-only item is listed under unknowns.

## Verifier corrections (authoritative)

- **Claim:** redis-py 8.1.0 'Default protocol is None (RESP2)' and 'protocol=2 explicit RESP2; default is None -> RESP2'. The report builds all its reply parsing (section 6: FT.SEARCH `[total, key, [f,v...]]`, FT.AGGREGATE, FT.PROFILE, FT.HYBRID) on RESP2.
  - **Correction:** In redis-py 8.1.0, protocol=None falls back to DEFAULT_RESP_VERSION = 3. Source: redis/utils.py:283, used in connection.py:921-930 (`int(None)` -> TypeError -> DEFAULT_RESP_VERSION) and in check_protocol_version. A default client sends `HELLO 3 AUTH default <pw>`; with protocol=2 it sends plain `AUTH`. Against a fake RESP3 socket, `r.execute_command('FT.SEARCH','idx','*')` on a default client returned a dict ({b'total_results': 0, b'results': []}), not a list. The reason is that legacy_responses=True only reshapes core commands (_parsers/response_callbacks.py:484-511); raw FT.* replies are never reshaped. protocol=2 (or `?protocol=2` on a URL) is therefore mandatory for every RESP2 parse in the report, not optional. The old notebook's `GuardedTracedRedis.from_url(url, decode_responses=False, socket_timeout=10)` (notebook.py:228-230) negotiates RESP3, so `_res[0]` and `range(1, len(_res), 2)` in _recall/_grammars/_router (notebook.py:479-493, 549-563, 638-643) would break against a live Redis 8. The audit did not catch this.
  - **Source:** /tmp/fc/hello_probe.py and /tmp/fc/fake_resp3.py (local fake sockets, no Redis) under uv venv with redis==8.1.0; /tmp/fc/venv/Lib/site-packages/redis/utils.py:283, connection.py:921-930, _parsers/response_callbacks.py:484-511
- **Claim:** redisvl 0.27.2 'emits byte-identical query strings' / 'generated offline; identical to the raw commands'.
  - **Correction:** The KNN and range strings are equivalent, not byte-identical. Actual argv order is query, RETURN, SORTBY, DIALECT, LIMIT (`VectorQuery.get_args()` -> ['*=>[KNN 3 @vec $vector AS vector_distance]','RETURN',2,'text','vector_distance','SORTBY','vector_distance','ASC','DIALECT',2,'LIMIT',0,3]). The report's raw form orders things differently and uses different alias and param names (dist/BLOB vs vector_distance/vector). TextQuery is semantically different: `TextQuery(text='refund policy', text_field_name='body')` emits `@body:(refund | policy)`, an OR of tokens with default stopwords='english', while the report's raw `@body:(refund policy)` is an AND/intersection. The 'same thing in redisvl' cell would therefore show different BM25 hit sets.
  - **Source:** /tmp/fc/rvl2.py output under redisvl==0.27.2; inspect.signature(TextQuery.__init__)
- **Claim:** 'BM25 renamed to BM25STD in 8.4 ... For older servers, detect the version and use BM25.'
  - **Correction:** BM25STD predates 8.4. The RediSearch 2.10 release notes (minimum Redis 7.4) include 'Fix underflow in BM25STD' (#7259, v2.10.25). redisvl 0.27.2 also defaults its FT.AGGREGATE-based (pre-8.4) hybrid path to text_scorer='BM25STD' (redisvl/query/aggregate.py:110). What changed in 8.4 is the default scorer (search-default-scorer), not whether BM25STD exists. On every Cloud version from 7.4 up, BM25STD can be sent as-is. A BM25 fallback is unnecessary; BM25 is the deprecated name.
  - **Source:** https://redis.io/docs/latest/operate/oss_and_stack/stack-with-enterprise/release-notes/redisearch/redisearch-2.10-release-notes/; https://redis.io/docs/latest/develop/whats-new/8-4/; /tmp/fc/venv/Lib/site-packages/redisvl/query/aggregate.py:110
- **Claim:** FT.PROFILE syntax is `FT.PROFILE index <SEARCH|HYBRID|AGGREGATE> [LIMITED] QUERY query`, implying the HYBRID profile type is usable.
  - **Correction:** The page's syntax_fmt shows HYBRID, but its machine-readable arguments list only SEARCH and AGGREGATE. Both the Redis 8.4 and Redis Cloud 8.4 known limitations say '`FT.PROFILE`, `FT.EXPLAIN`, and `FT.EXPLAINCLI` don't include `FT.HYBRID` options'. Treat FT.PROFILE HYBRID as unavailable on 8.4 and feature-detect it on 8.6. FT.PROFILE SEARCH (Planner X-ray) is unaffected.
  - **Source:** https://redis.io/docs/latest/commands/ft.profile/ (metadata arguments); https://redis.io/docs/latest/operate/rc/changelog/version-release-notes/8-4/
- **Claim:** Pins `marimo==0.24.2, redis==8.1.0, numpy>=2.0, model2vec==0.9.0` are sufficient for the column, while the wow ideas (recall lab, threshold curve, faceted browse) use mo.ui.altair_chart.
  - **Correction:** altair is not a marimo dependency (marimo 0.24.2 requires_dist has no altair or pandas). `mo.ui.altair_chart({})` raises ModuleNotFoundError: 'altair is required to use `mo.ui.altair_chart`'. Add altair to the PEP 723 deps, or use a dependency-free chart.
  - **Source:** importlib.metadata.requires('marimo') and a direct call in /tmp/fc/venv (marimo 0.24.2)

### Verifier: additional facts

- Under default RESP3, the documented RESP3 reply shapes apply to raw execute_command. FT.SEARCH, FT.AGGREGATE and FT.HYBRID return maps (total_results, results[...], attributes, format, warning). FT.PROFILE returns a map with keys Results and Profile. FT.INFO returns a map. FT._LIST returns a Set. Any parser written for RESP2 lists must pin protocol=2. The URL form `redis://default:pw@host:port?protocol=2` also works (connection_kwargs['protocol'] == 2).  _(src: https://redis.io/docs/latest/commands/ft.search/, .../ft.aggregate/, .../ft.profile/, .../ft._list/ (Return information); /tmp/fc offline check `Redis.from_url('redis://default:x@h:1?protocol=2')`)_
- With the default RESP3 handshake, redis-py 8.1.0 also sends 3 CLIENT commands on connect (seen on the fake socket: HELLO, CLIENT, CLIENT, CLIENT). These go through the connection handshake, not execute_command, so the guard and tracer never see them. They are harmless but will not appear in the trace.  _(src: /tmp/fc/fake_resp3.py output)_
- A cheaper model download: `snapshot_download('minishlab/potion-base-8M', allow_patterns=['config.json','model.safetensors','tokenizer.json','README.md'])` fetched 4 files (~30 MB, 3.2 s), skipping the 30 MB ONNX file, and `StaticModel.from_pretrained(<that path>)` loaded in 0.11 s. Caveat for the report's workaround: in huggingface_hub 1.33.0, `snapshot_download(repo, local_files_only=True)` without the same allow_patterns raises IncompleteSnapshotError on a partial snapshot ('6 file(s) are missing'). Passing identical allow_patterns with local_files_only=True works (0.0 s, HF_HUB_OFFLINE=1). model2vec's layout check needs only config.json, model.safetensors and tokenizer.json.  _(src: /tmp/fc/m2v.py and /tmp/fc/m2v2.py with HF_HOME=/tmp/fc/hf; model2vec/persistence/datamodels.py:28-35)_
- model2vec's force_download flag is never forwarded to huggingface_hub. persistence.py:145-147 calls `snapshot_download(str(path.as_posix()), repo_type='model', token=token)` with no force_download. force_download only controls whether the local-cache shortcut is tried, so on Windows (where the shortcut always misses) it has no effect either way.  _(src: /tmp/fc/venv/Lib/site-packages/model2vec/persistence/persistence.py:135-149)_
- huggingface-hub 2.0.0 was released 2026-09-24, but tokenizers 0.23.2 pins 'huggingface-hub>=0.16.4,<2.0', so the notebook's deps currently resolve to huggingface-hub 1.33.0. model2vec does not declare huggingface_hub directly, and the snapshot_download workaround depends on that transitive pin.  _(src: https://pypi.org/pypi/huggingface-hub/json; importlib.metadata.requires('tokenizers') in /tmp/fc/venv)_
- Scoping every FT.* index argument to the session prefix (report section 8) would also block the 'read-only peek at Iris internals' wow idea (FT.INFO memory:{store_id}:ltm). If that cell is kept, it needs an explicit read-only exception (FT._LIST, FT.INFO, perhaps FT.SEARCH ... LIMIT 0 0) that never permits DD, DEL or HSET on foreign keys. Separately, the current guard allows `SCAN 0 MATCH *` (read-only, but it enumerates foreign key names).  _(src: report api_surface section 8 and wow_ideas; /tmp/fc/old/probe_guard.py)_
- FT.HYBRID's pre-filter policy keyword is `POLICY [ADHOC_BF|BATCHES] [BATCH_SIZE n]` inside the VSIM FILTER clause, not HYBRID_POLICY. HYBRID_POLICY is the FT.SEARCH KNN keyword. FT.HYBRID metrics also do not appear in FT.INFO or INFO on 8.4.  _(src: https://redis.io/docs/latest/commands/ft.hybrid/ syntax_fmt; https://redis.io/docs/latest/develop/whats-new/8-4/ known limitations)_
- SVS-VAMANA also has runtime params USE_SEARCH_HISTORY (OFF/ON/AUTO) and SEARCH_BUFFER_CAPACITY (default SEARCH_WINDOW_SIZE) for two-level compression, which the report omits.  _(src: https://redis.io/docs/latest/develop/ai/search-and-query/vectors/ (Index-specific query parameters, SVS-VAMANA))_
- The '1536 dims' question in the reference repo. GuardrailService embeds with settings.openai_embedding_model, default 'text-embedding-3-small' (backend/app/settings.py:27; guardrail_service.py:29,55,91), which is 1536-d at default dimensions (dims not verified live). The Radish input router uses HFTextVectorizer with radish_hf_embedding_model default 'sentence-transformers/all-mpnet-base-v2' (settings.py:80-82; radish_input_router.py:120-122), a different embedder.  _(src: C:/Users/NickCooper/projects/demo/redis-iris-demos/backend/app/settings.py, guardrail_service.py, radish_input_router.py)_

Features like the COLLECT reducer (since 8.8.0) would work locally and fail on Cloud, so pin the local fallback to redis:8.6 or 8.4 to mirror Cloud.  _(src: hub.docker.com tag checks; https://redis.io/docs/latest/commands/ft.aggregate/ (collect since 8.8.0); version-management page)_

## Secrets

- **REDIS_HOST** — Redis Cloud console -> Databases -> your free database -> Configuration tab -> Access section -> Public endpoint (host part before the colon). Static endpoints look like redis-<port>.c<N>.<region>...; dynamic ones like <word>-<word>-<word>-<N>.db.redis.io. (https://cloud.redis.io)
- **REDIS_PORT** — Same Access -> Public endpoint (the number after the colon). (https://cloud.redis.io)
- **REDIS_PASSWORD** — Database -> Configuration -> Security -> Default user -> Configure, then click the eye icon. Or open the Connect wizard and copy the redis-cli / Python snippet. (https://cloud.redis.io)
- **REDIS_USERNAME** — Always `default` unless Role-Based Access Control is enabled and the default user turned off. No lookup needed for a free DB. (https://redis.io/docs/latest/operate/rc/databases/connect/)
- **REDIS_SSL (or the scheme of REDIS_URL)** — Set False / use `redis://` for the free 30 MB tier (TLS is not available on Free and is off by default elsewhere). Only set True / `rediss://` if the user enabled TLS on a paid Essentials/Pro DB (Security -> Transport layer security toggle, then download redis_ca.pem). (https://redis.io/docs/latest/operate/rc/security/database-security/tls-ssl/)
- **REDIS_URL (optional convenience)** — Compose `redis://default:<REDIS_PASSWORD>@<REDIS_HOST>:<REDIS_PORT>`. Sign up for a free DB at https://redis.io/try-free/ (Sign up -> activate email -> 'Try 30 MB for free' -> Create database). No embedding or LLM API key is needed for this column (model2vec runs locally). (https://redis.io/try-free/)

## 4. Command grammar (docs-verified unless marked)
Token-count rule for VECTOR attributes = 2 x number of name/value pairs. Docs examples: FLAT 6, HNSW 10, SVS-VAMANA 12.
```
FT.CREATE {idx} ON HASH PREFIX 1 {prefix} [TEMPORARY 3600] SCHEMA
  title TEXT [WEIGHT 2.0] [NOSTEM] [WITHSUFFIXTRIE] [SORTABLE]
  body TEXT
  category TAG [SEPARATOR ,] [SORTABLE]
  price NUMERIC [SORTABLE]
  vec VECTOR FLAT 6 TYPE FLOAT32 DIM 256 DISTANCE_METRIC COSINE
  -- or --  vec VECTOR HNSW 10 TYPE FLOAT32 DIM 256 DISTANCE_METRIC COSINE M 16 EF_CONSTRUCTION 200
  -- or --  vec VECTOR HNSW 14 TYPE FLOAT32 DIM 256 DISTANCE_METRIC COSINE M 16 EF_CONSTRUCTION 200 EF_RUNTIME 10 EPSILON 0.01
  -- or --  vec VECTOR SVS-VAMANA 12 TYPE FLOAT32 DIM 256 DISTANCE_METRIC COSINE GRAPH_MAX_DEGREE 32 CONSTRUCTION_WINDOW_SIZE 200 COMPRESSION LVQ8   (Redis >=8.2)
```
- KNN (DIALECT 2 is mandatory; default dialect is 1):
`FT.SEARCH {idx} "*=>[KNN {k} @vec $BLOB AS dist]" PARAMS 2 BLOB <bytes> SORTBY dist ASC LIMIT 0 {k} RETURN 2 title dist DIALECT 2`
- The default LIMIT is 0 10, so if k>10 you MUST add `LIMIT 0 k`. Without SORTBY, results sort by score.
- Per-query HNSW EF_RUNTIME (docs example form): `"*=>[KNN 10 @vec $BLOB]=>{$EF_RUNTIME: $EF; $YIELD_DISTANCE_AS: dist}" PARAMS 4 EF 150 BLOB <bytes> SORTBY dist DIALECT 2`
- SVS query knob is `SEARCH_WINDOW_SIZE`; FLAT has no runtime params.
- VECTOR_RANGE: `FT.SEARCH {idx} "@vec:[VECTOR_RANGE $R $BLOB]=>{$YIELD_DISTANCE_AS: dist}" PARAMS 4 R 0.35 BLOB <bytes> SORTBY dist LIMIT 0 100 DIALECT 2`. Add `$EPSILON: 0.5;` inside the braces (HNSW). Range queries have no default distance field name and also default to LIMIT 0 10.
- Pre-filters (KNN/range accept them):
  - TAG: `@category:{cards}`, `@category:{cards|loans}`, `-@category:{fees}`.
  - NUMERIC: `@price:[500 1000]`, `@price:[(500 +inf]` (redisvl emits this form); DIALECT 2 also allows `@price>=500`.
  - TEXT: `@body:(refund policy)`, `@body:(a|b)`, `@model:ka*`, `@brand:*bikes`, `@description:(%optamized%)` (no quotes around the fuzzy term), `%%x%%` and `%%%x%%%` for distance 2 and 3.
  - Combine: `(@category:{cards} @price:[0 100])=>[KNN 5 @vec $BLOB AS dist]`. Text boost: `... => { $weight: 5.0; }`.
  - Filter mode override: `=>[KNN 10 @vec $BLOB HYBRID_POLICY ADHOC_BF]` or `HYBRID_POLICY BATCHES BATCH_SIZE $BATCH_SIZE`.
- BM25/full text: `FT.SEARCH {idx} "@body:(refund policy)" SCORER BM25STD WITHSCORES [EXPLAINSCORE] LIMIT 0 5 DIALECT 2`. Scorers: TFIDF, TFIDF.DOCNORM, BM25STD (default; `BM25` renamed to `BM25STD` in 8.4, and `BM25` is now deprecated), BM25STD.NORM, BM25STD.TANH (`BM25STD_TANH_FACTOR Y`, default 4), DISMAX, DOCSCORE, HAMMING. EXPLAINSCORE requires WITHSCORES. For older servers, detect the version and use `BM25`.
- FT.AGGREGATE (RESP2 reply = `[ignored_int, [k,v,...], ...]`):
`FT.AGGREGATE {idx} "*" GROUPBY 1 @category REDUCE COUNT 0 AS n REDUCE AVG 1 @price AS avg_price SORTBY 2 @n DESC MAX 10 DIALECT 2`
  - Reducers: COUNT, COUNT_DISTINCT, COUNT_DISTINCTISH, SUM, MIN, MAX, AVG, STDDEV, QUANTILE, TOLIST, FIRST_VALUE, RANDOM_SAMPLE (COLLECT is 8.8+ only, so not on Cloud).
  - Pipeline stages run in the order written. Group fields should be SORTABLE (docs advice) or `LOAD`ed.
  - Vector inside aggregate: `"@vec:[VECTOR_RANGE $r $BLOB]=>{$YIELD_DISTANCE_AS: vector_distance}" GROUPBY 1 @category REDUCE MIN 1 @vector_distance AS best ... PARAMS 4 r 0.7 BLOB <bytes> DIALECT 2`.
- FT.HYBRID (Redis >=8.4; argv verified from redis-py 8.1.0 classes, not from a server):
`FT.HYBRID {idx} SEARCH "{text}" SCORER BM25STD YIELD_SCORE_AS text_score VSIM @vec $q KNN 4 K 10 EF_RUNTIME 50 YIELD_SCORE_AS vec_score COMBINE RRF 4 WINDOW 20 CONSTANT 60 LOAD 2 @title @category LIMIT 0 5 PARAMS 2 q <bytes>`
  - `COMBINE LINEAR 4 ALPHA 0.7 BETA 0.3` is the alternative. `RANGE 2 RADIUS 0.5 [EPSILON x]` replaces KNN. Defaults: RRF WINDOW 20, CONSTANT 60, LIMIT 10, K 10, SCORER BM25STD.
  - Counts include every following token of the clause.
  - Cloud 8.4 limits: `EXPLAINSCORE`, `SHARD_K_RATIO`, `YIELD_DISTANCE_AS`, `WITHCURSOR` unavailable; FILTER after COMBINE unsupported. Wrap in try/except and fall back to client-side RRF (`sum 1/(60+rank)`).
  - RESP2 reply parses as flat key/value pairs `total_results, results (list of [k,v,...]), warnings, execution_time` (redis-py `_parse_hybrid_search`, commands.py:298). The docs' RESP2 description says something different.
  - redis-py's own wrapper `ft(idx).hybrid_search(...)` is `@experimental_method`.
- Introspection:
  - `FT.INFO {idx}` (RESP2 flat list). Useful keys: `num_docs, vector_index_sz_mb, total_index_memory_sz_mb, inverted_sz_mb, hash_indexing_failures, indexing, percent_indexed, attributes`.
  - `FT.PROFILE {idx} SEARCH QUERY "<query>" PARAMS ... DIALECT 2` returns `[results, profile]`. Profile iterators expose `Vector search mode`: STANDARD_KNN, RANGE_QUERY, HYBRID_ADHOC_BF, HYBRID_BATCHES, HYBRID_BATCHES_TO_ADHOC_BF. Batch mode adds `Batches number`, `Largest batch size`.
  - `FT.EXPLAINCLI {idx} "<q>" DIALECT n`, `FT._LIST`.
  - Cleanup: `FT.DROPINDEX {idx} [DD]` (DD deletes the documents and is @dangerous).

## 5. Vector blobs
FLOAT32 = `np.asarray(v, np.float32).tobytes()`, length must equal DIM x 4 or indexing silently fails (watch `hash_indexing_failures`). FLOAT16 = `.astype(np.float16).tobytes()`. INT8 (Redis >=8.0) = e.g. `np.round(unit*127).astype(np.int8).tobytes()` (my suggestion, unverified live). BFLOAT16 needs `ml_dtypes`. SVS-VAMANA accepts only FLOAT16/FLOAT32.

## 6. RESP2 reply parsing (raw execute_command, decode_responses=False)
- FT.SEARCH: `[total, key, [f,v,...], key, [f,v,...]]`; with WITHSCORES: `[total, key, score, [f,v,...], ...]`; with NOCONTENT: `[total, key, key, ...]`. Bytes everywhere; decode with utf-8.
- FT.AGGREGATE: first element is meaningless, then one `[f,v,...]` per row. FT.PROFILE: `[search_reply, profile_nested_arrays]`.

## 7. redisvl equivalents (redisvl 0.27.2, generated offline; identical to the raw commands)
- `VectorQuery(vector=v, vector_field_name="vec", return_fields=["text"], num_results=3)` -> `*=>[KNN 3 @vec $vector AS vector_distance] RETURN 2 text vector_distance SORTBY vector_distance ASC DIALECT 2 LIMIT 0 3`
- `VectorRangeQuery(..., distance_threshold=0.35)` -> `@vec:[VECTOR_RANGE $distance_threshold $vector]=>{$YIELD_DISTANCE_AS: vector_distance} RETURN 2 text vector_distance SORTBY vector_distance ASC DIALECT 2 LIMIT 0 10`
- `(Tag("owner")=="alice") & (Num("year")>2020)` -> `((@owner:{alice} @year:[(2020 +inf]))=>[KNN 3 @vec $vector AS vector_distance] ...`
- `TextQuery` -> `@text:(shellfish | allergy) SCORER BM25STD WITHSCORES RETURN 1 text DIALECT 2 LIMIT 0 3`
- `HybridQuery` requires Redis >=8.4.0 and redis-py >=7.1.0 (redisvl/query/hybrid.py:9).
- SemanticCache uses `VectorRangeQuery` on a FLAT index, default `distance_threshold=0.1`. The router does group_by -> sort_by(max=max_k) -> filter (redisvl/extensions/router/semantic.py:427-455).

## 8. Guard changes the new column needs
- Scope index names: FT.CREATE/SEARCH/AGGREGATE/PROFILE/INFO/DROPINDEX/HYBRID/EXPLAINCLI arg[1] must start with the session prefix.
- Reject FT.CREATE unless PREFIX values start with the session prefix.
- Reject `DD` unless the index is ours.
- Check every key for DEL/UNLINK.

## Explorable parameters

- **ALGORITHM** — Vector index type: exact scan vs graph ANN vs Intel SVS graph with optional compression Values: FLAT (6 attr tokens; exact; docs: < 1M vectors) | HNSW (10 or 14 tokens) | SVS-VAMANA (12 tokens; Redis >=8.2; Cloud/free availability unverified) _(src: https://redis.io/docs/latest/develop/ai/search-and-query/vectors/)_
- **DISTANCE_METRIC** — How distance is computed; smaller = closer Values: COSINE (1 - cos, bounded by 2) | IP (1 - u.v) | L2. On unit vectors COSINE == IP. L2 appears to return the SQUARED Euclidean distance (docs' FT.PROFILE example scores 2, 2, 10 for diffs of norm sqrt2, sqrt2, sqrt10), so on unit vectors L2 = 2 x COSINE. _(src: vectors doc distance-metrics table; https://redis.io/docs/latest/commands/ft.profile/ example arithmetic)_
- **TYPE** — Stored element type, drives memory Values: FLOAT32 | FLOAT64 | FLOAT16, BFLOAT16 (need >=2.10) | INT8, UINT8 (need >=8.0); SVS-VAMANA only FLOAT16/FLOAT32. Blob bytes must match TYPE x DIM. _(src: vectors doc FLAT/HNSW/SVS required-attribute tables)_
- **M** — HNSW max outgoing edges per node (layer 0 uses 2*M); more = accuracy + memory + build time Values: default 16; suggest slider 2-64; use M 4 with EF_CONSTRUCTION 10 to make a deliberately weak graph for the recall lab _(src: vectors doc HNSW table; faiss sim (not RediSearch))_
- **EF_CONSTRUCTION** — HNSW candidate list size at build time Values: default 200; slider 8-500 _(src: vectors doc HNSW table)_
- **EF_RUNTIME** — HNSW candidate list at query time (accuracy vs latency). Settable at FT.CREATE (index default) and overridable per query via `=>{$EF_RUNTIME: $EF}` or `EF_RUNTIME $EF` inside KNN brackets Values: default 10; slider 10-500. Not applicable to FLAT (no runtime params); disable the slider when FLAT is chosen _(src: vectors doc runtime parameters; KNN examples)_
- **EPSILON** — Range-query approximation factor: candidates within radius*(1+EPSILON) are scanned (HNSW and SVS) Values: default 0.01; per query `$EPSILON: 0.5` inside `=>{...}`; only meaningful for VECTOR_RANGE _(src: vectors doc; range query example)_
- **SVS-VAMANA GRAPH_MAX_DEGREE / CONSTRUCTION_WINDOW_SIZE / SEARCH_WINDOW_SIZE** — SVS graph analogues of 2*M, EF_CONSTRUCTION, EF_RUNTIME Values: defaults 32 / 200 / 10; SEARCH_WINDOW_SIZE is also the per-query knob (KNN only) _(src: vectors doc SVS-VAMANA tables)_
- **SVS COMPRESSION (+ TRAINING_THRESHOLD, REDUCE)** — Vector quantization: LVQ8, LVQ4, LVQ4x4, LVQ4x8, LeanVec4x8, LeanVec8x8. On non-Intel/OSS builds any COMPRESSION falls back to global-min/max 8-bit scalar quantization; LeanVec REDUCE defaults to DIM/2; TRAINING_THRESHOLD default 10*1024 Values: omit | LVQ8 | LVQ4x4 | LeanVec4x8 ... _(src: vectors doc SVS warning; svs-compression page)_
- **KNN k** — Number of nearest neighbours; KNN always returns min(k, N) rows unless a filter leaves fewer Values: `KNN $K` with PARAMS; MUST add `LIMIT 0 k` because default LIMIT is 0 10 _(src: vectors doc Important notes)_
- **VECTOR_RANGE radius** — Max distance for a hit; can return 0 rows (thus a cache MISS is expressible). COSINE is bounded by 2 Values: `@vec:[VECTOR_RANGE $R $BLOB]=>{$YIELD_DISTANCE_AS: dist}`; slider 0.05-1.0. Calibrate per embedder: with potion-base-8M paraphrase 0.221 vs unrelated 0.825 _(src: vectors doc range queries; calibrate.py output)_
- **TAG pre-filter** — Exact-match narrowing before/inside KNN Values: `@category:{a}`, `{a|b}`, `-@category:{c}`, combine with `(...)=>[KNN ...]` _(src: combined queries page; vectors doc filters)_
- **NUMERIC pre-filter** — Range narrowing Values: `@price:[min max]`, exclusive `[(min +inf]`, DIALECT 2 comparison ops `@price>=500` _(src: combined queries; dialects page; redisvl output)_
- **TEXT pre-filter / full-text query** — Word, phrase, prefix, suffix, fuzzy matching without embeddings Values: `@body:(a b)`, `@body:(a|b)`, `pre*` (>=2 chars), `*suf` / `*mid*` (faster with WITHSUFFIXTRIE), `%typo%` (distance 1), `%%typo%%` (2), `%%%typo%%%` (3), SLOP n, INORDER, `=> { $weight: 5.0; }` _(src: full-text query page; FT.SEARCH page)_
- **HYBRID_POLICY / BATCH_SIZE** — Force the filtered-KNN execution mode (BATCHES vs ADHOC_BF); default is auto-chosen by heuristics and can switch mid-query Values: `HYBRID_POLICY ADHOC_BF` | `HYBRID_POLICY BATCHES BATCH_SIZE 50`. Observe the chosen mode via FT.PROFILE `Vector search mode` _(src: vectors doc filter mode; FT.PROFILE page)_
- **SCORER** — Text relevance function Values: BM25STD (default from 8.4; older name BM25) | BM25STD.NORM | BM25STD.TANH [BM25STD_TANH_FACTOR 4] | TFIDF | TFIDF.DOCNORM | DISMAX | DOCSCORE | HAMMING. Add WITHSCORES, and EXPLAINSCORE to see the formula _(src: scoring page; whats-new 8.4)_
- **FT.AGGREGATE GROUPBY / REDUCE** — Facets and per-group stats; stage order matters (SORTBY ... MAX n trims before a later FILTER) Values: `GROUPBY 1 @field REDUCE <COUNT|COUNT_DISTINCT|COUNT_DISTINCTISH|SUM|MIN|MAX|AVG|STDDEV|QUANTILE|TOLIST|FIRST_VALUE|RANDOM_SAMPLE> nargs args AS name`; then `SORTBY 2 @n DESC MAX 10`, `APPLY`, `FILTER`, `LIMIT` _(src: FT.AGGREGATE page)_
- **FT.HYBRID COMBINE** — Fuse BM25 text ranking and vector ranking server-side Values: `COMBINE RRF 4 WINDOW 20 CONSTANT 60` | `COMBINE LINEAR 4 ALPHA a BETA b`; `VSIM @vec $q KNN 4 K 10 EF_RUNTIME 50` or `RANGE 2 RADIUS r`; Redis >=8.4 only _(src: FT.HYBRID page; redis-py 8.1.0 hybrid_query argv)_
- **DIALECT** — Query parser version; default 1; vector queries require 2 Values: always append `DIALECT 2`; FT.EXPLAINCLI ... DIALECT 1 vs 2 on `-hello world` shows the difference _(src: dialects page)_
- **Index options: TEMPORARY / SKIPINITIALSCAN / INDEXALL / STOPWORDS / LANGUAGE** — Self-expiring index (docs say expiry also drops its documents), no initial scan, compact doc-id index (8.0+), custom stopwords, stemmer language Values: `TEMPORARY 3600`, `SKIPINITIALSCAN`, `INDEXALL ENABLE`, `STOPWORDS 0`, `LANGUAGE english` _(src: FT.CREATE page)_
- **Field options** — Per-field behaviour Values: TEXT: WEIGHT, NOSTEM, PHONETIC dm:en, WITHSUFFIXTRIE, SORTABLE [UNF], INDEXEMPTY, INDEXMISSING; TAG: SEPARATOR, CASESENSITIVE; NUMERIC: SORTABLE _(src: FT.CREATE page)_

## Safety concerns

- Free tier is one DB per account, so it is likely the user's only Essentials DB. Point the notebook at a scratch DB and print DBSIZE and the FT._LIST contents before any write. Keep the consent button.
- No server-side ACL scoping: ACL SETUSER is unsupported on Cloud and FLUSHALL/FLUSHDB ARE supported, so the client-side guard is the only fence. The current guard does not scope FT.* index names, allows `FT.DROPINDEX <any> DD` (deletes another index's documents), allows FT.CREATE with an empty or foreign PREFIX (can index the whole keyspace), checks only the first key of DEL/UNLINK, and is bypassed by pipelines. Fix all of these (see api_surface section 8) and add tests for each.
- Always namespace with a per-session random prefix for both keys and index names (`demo:<run>:` / `iris_search_<run>`), and drop only indexes whose names match this session's prefix. Stale indexes from earlier kernel sessions stay behind; use FT.CREATE ... TEMPORARY <seconds> so they self-expire (docs say expiry drops their docs too; behaviour on Cloud unverified) and/or list `FT._LIST` for our own naming pattern on connect and offer cleanup.
- Clean-up path: `FT.DROPINDEX <our idx> DD` (async) removes index and docs in one call, or SCAN MATCH `<prefix>*` then UNLINK plus FT.DROPINDEX. Also set EXPIRE on every hash (or TEMPORARY index) so an abandoned demo does not linger.
- Free-tier throttles: 100 ops/sec, 30 connections, 30 MB, 5 GB/month. Use a single client (close it in teardown), keep corpora at a few hundred to ~3000 docs (30-60 s of writes at the cap), batch writes with progress, and gate expensive UI (sliders that fire queries) behind mo.ui.run_button or mo.ui.form, since marimo re-executes dependent cells on every change. Docs say Redis will notify before limiting, so enforcement style is unknown.
- Do not ship `rediss://` defaults for the free tier (no TLS available); do offer REDIS_SSL for paid Essentials/Pro where TLS can be enabled. Never echo the password: keep the password text input kind='password', and make sure the _cli trace never prints connection strings.
- The corpus and embeddings are local, but the first run downloads 61 MB from Hugging Face (ONNX file included). On locked-down networks fall back to the lexical hash embedder and show a loud warning, since paraphrase recall will not work.
- Vector blob correctness: a wrong DIM or TYPE makes indexing silently fail (`hash_indexing_failures` in FT.INFO). Poll `indexing`/`percent_indexed` and show failures instead of returning empty results.
- Redis 8.4 on Cloud has documented partial-result/duplicate caveats during atomic slot migration for FT.SEARCH/AGGREGATE/HYBRID, and 8.6 notes cursor misses during rebalancing; both are cluster events, low risk on a free DB but do not present result counts as exact in a timing demo.
- This research made no calls to any Redis, LangCache, Agent Memory or Context Retriever service and read no .env values (only key names from .env.example). Scratch files, temp HF cache (61 MB) and throwaway uv envs live in $TEMP/scratch; nothing under C:\Users\NickCooper\projects\demo was modified.
