### Design

The package `src/cairn_support/` (today `sample_data.py`, `embedder.py`, `formatting.py`, with a test that forbids it to import redis, niquests, or marimo) becomes the home of everything a learner does not need to read, and the notebook keeps the Iris protocol. The boundary rule changes to: the package never imports marimo, so everything in it works in an agent outside the notebook, and `sample_data.py` stays free of any protocol. `redis`, `niquests`, `openai`, `anthropic`, `numpy`, and `model2vec` are allowed in the other modules. `tests/test_cairn_support.py` changes accordingly.

New modules, each small:

- `settings.py`: `SETTINGS`, the ordered mapping of the nine names to where each is found (the text now inline in `env_check`), and `missing_settings()`. `env_check` keeps `import os`, the table rendering, `mo.stop`, and the Restart button, because those are the notebook's interface.
- `run_tag.py`: `RUN_TAG` and `KEY_PREFIX` (the getpass, hashlib, and socket code). The `run_tag` cell becomes one import line and a two-sentence comment on why every key carries the prefix.
- `llm.py`: `stream_llm(system_prompt, messages, model, max_tokens)`, an async generator that picks OpenAI or Anthropic by the model prefix and reads `LLM_API_KEY` from the environment inside. The `llm_client` cell becomes `from cairn_support.llm import stream_llm` and `AI_MODEL = "gpt-4o-mini"` with its one-line comment (`AI_MODEL` leaves `redis_client`, line 95 today, in the same edit context, because one cell owns a name). The client is built inside the generator, never at import, so a missing key still fails at the first turn and `llm_client` can stop taking `os`. The three turn functions that call it, `rss_turn`, `lcs_turn`, and `ams_turn`, pass `AI_MODEL` and `config.max_tokens` instead of `config`, so the package never sees a marimo type. The Context Retriever column has no chat and never calls it.
- `http.py`: `json_session(base_url, headers, timeout)` (the niquests session with pinned `Content-Type`, `Accept`, `User-Agent`, `disable_http3=True`) and `call(session, method, path, body) -> (status, payload, ms)` with the non-JSON fallback (`{"type": reason}` on a 403 HTML page). LangCache's `lcs_call` becomes a one-line wrapper over `call` and keeps its name, which `lc_build_md`, `lc_next_md`, and the README use. `crs_admin` and `crs_mcp` build their sessions with `json_session` (`base_url` optional, since the MCP session posts to the absolute `mcp_url`) and keep returning the response. `crs_list_tools` and `crs_call` read `status_code`, `json()`, and `text[:400]` for the not-JSON case, which the `{"type": reason}` fallback drops. Their `-> niquests.Response` annotations go, since `niquests` leaves the notebook. Name the module `web.py` or `sessions.py` rather than `http.py`, which shadows the stdlib name for anything that puts the package folder on `sys.path`. The Bearer header line stays visible in `lc_connect`, because "one Bearer token on both" is principle 1.
- No `redis_url.py`. `redis.connection.parse_url(url)` in redis-py 8.1.0 returns `username`, `password` (unquoted, so `p%40ss` reads `p@ss`), `host`, `port`, `db` when the URL has a path, and `connection_class` `SSLConnection` for `rediss://`, checked in the venv. `redis` is already in column 0, so `urlsplit` and `unquote` leave the notebook with no new module and no new name. `crs_connection_config` stays visible and builds the dict (`addr`, `username`, `password`, `db`, `tls_enabled`, `pool_size`, `min_idle_conns`) from it, because the dict is principle 2. If Nick prefers the plan's own parser, `redis_url.py` as first written is fine, at one more visible name.
- `types.py`: the complex types the visible signatures use, imported where needed.
